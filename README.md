# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

### `TPayment`
Тип способа оплаты:

```ts
type TPayment = 'card' | 'cash';
```

### `IProduct`
Описывает товар магазина:

```ts
interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}
```

Поля:
`id — уникальный идентификатор товара;`
`description — описание товара;`
`image — путь к изображению товара;`
`title — название товара;`
`category — категория товара;`
`price — стоимость товара, null — товар недоступен для покупки.`

### `IBuyer`
Описывает данные покупателя:

```ts
interface IBuyer {
    payment: TPayment;
    email: string;
    phone: string;
    address: string;
}
```

Поля:
`payment — способ оплаты;`
`email — электронная почта покупателя;`
`phone — номер телефона;`
`address — адрес доставки.`

### `IBuyerData`
Используется для хранения текущих данных покупателя.  
Поле `payment` может быть `null`, если способ оплаты ещё не выбран.

```ts
interface IBuyerData {
    payment: TPayment | null;
    email: string;
    phone: string;
    address: string;
}
```

Поля:
`payment — способ оплаты, null — способ оплаты ещё не выбран;`
`email — электронная почта покупателя;`
`phone — номер телефона;`
`address — адрес доставки.`

### `IBuyerErrors`
Описывает ошибки валидации данных покупателя.

```ts
interface IBuyerErrors {
    payment?: string;
    email?: string;
    phone?: string;
    address?: string;
}
```

Поля:
`payment — текст ошибки выбора способа оплаты;`
`email — текст ошибки заполнения электронной почты;`
`phone — текст ошибки заполнения телефона;`
`address — текст ошибки заполнения адреса.`

### `IProductsResponse`
Описывает ответ сервера со списком товаров.

```ts
interface IProductsResponse {
    total: number;
    items: IProduct[];
}
```

Поля:
`total — общее количество товаров;`
`items — массив товаров каталога.`

### `IOrder`
Описывает данные заказа, отправляемые на сервер.

```ts
interface IOrder extends IBuyer {
    total: number;
    items: string[];
}
```

Поля:
`total — общая стоимость заказа;`
`items — массив идентификаторов товаров в заказе.`

### `IOrderResponse`
Описывает ответ сервера после успешного оформления заказа.

```ts
interface IOrderResponse {
    id: string;
    total: number;
}
```

Поля:
`id — уникальный идентификатор заказа;`
`total — итоговая стоимость заказа.`

## Модели данных

### `Products`
Хранит каталог товаров и товар, выбранный для подробного просмотра.

Конструктор:
- `constructor(events: IEvents)` — принимает брокер событий.

Поля:
- `items: IProduct[]` — каталог товаров;
- `selectedItem: IProduct | null` — выбранный товар.
- `events: IEvents` — брокер событий.

Методы:
- `setItems(items: IProduct[]): void` — сохраняет товары и генерирует событие изменения каталога;
- `getItems(): IProduct[]` — получить каталог;
- `getItem(id: string): IProduct | undefined` — найти товар по `id`;
- `setSelectedItem(item: IProduct): void` — сохраняет выбранный товар и генерирует событие его выбора.
- `getSelectedItem(): IProduct | null` — получить выбранный товар.

### `Basket`
Хранит товары, добавленные в корзину.

Конструктор:
- `constructor(events: IEvents)` — принимает брокер событий.

Поля:
- `items: IProduct[]` — товары в корзине.
- `events: IEvents` — брокер событий.

Методы:
- `getItems(): IProduct[]` — получить товары корзины;
- `addItem(item: IProduct): void` — добавляет товар и генерирует событие изменения корзины;
- `removeItem(item: IProduct): void` — удаляет товар и генерирует событие изменения корзины;
- `clear(): void` — очищает корзину и генерирует событие её изменения.
- `getTotal(): number` — получить общую стоимость;
- `getCount(): number` — получить количество товаров;
- `hasItem(id: string): boolean` — проверить наличие товара.

### `Buyer`
Хранит данные покупателя и отвечает за их валидацию.

Конструктор:
- `constructor(events: IEvents)` — принимает брокер событий.

Поля:
- `payment: TPayment | null` — способ оплаты;
- `email: string` — email;
- `phone: string` — телефон;
- `address: string` — адрес.
- `events: IEvents` — брокер событий.

Методы:
- `setPayment(payment: TPayment): void` — сохраняет способ оплаты и генерирует событие изменения данных;
- `setEmail(email: string): void` — сохраняет email и генерирует событие изменения данных;
- `setPhone(phone: string): void` — сохраняет телефон и генерирует событие изменения данных;
- `setAddress(address: string): void` — сохраняет адрес и генерирует событие изменения данных;
- `getData(): IBuyerData` — получить все данные;
- `clear(): void` — очищает данные покупателя и генерирует событие их изменения.
- `validate(): IBuyerErrors` — проверить заполненность полей.

## События приложения

### События представления

- `basket:open` — нажатие на кнопку открытия корзины.

- `modal:close` — нажатие на крестик или на область за пределами модального окна.

- `card:select` — выбор товара для подробного просмотра. Передаёт идентификатор товара (`id: string`).

- `card:action` — нажатие на кнопку покупки или удаления товара в карточке подробного просмотра.

- `basket:remove` — нажатие на кнопку удаления товара из корзины. Передаёт идентификатор товара (`id: string`).

- `order:open` — нажатие на кнопку оформления заказа.

- `form:change` — изменение значения поля формы. Передаёт название поля (`field: string`) и его значение (`value: string`).

- `order:submit` — отправка первой формы оформления заказа.

- `contacts:submit` — отправка второй формы оформления заказа.

- `payment:change` — выбор способа оплаты. Передаёт выбранный способ оплаты (`payment: TPayment`).

- `modal:close` — нажатие на крестик, область за пределами модального окна или кнопку «За новыми покупками!».

### События моделей данных

- `products:changed` — изменение массива товаров каталога.

- `product:selected` — изменение выбранного для просмотра товара.

- `basket:changed` — изменение содержимого корзины.

- `buyer:changed` — изменение данных покупателя.

## Презентер

Презентер реализован в файле `src/main.ts`. Отвечает за взаимодействие между моделями данных, компонентами представления и коммуникационным слоем.

Обрабатывает события приложения, получает данные из моделей и передаёт их компонентам представления.

При получении события `products:changed` получает товары из модели `Products`, создаёт карточки товаров и передаёт их компоненту `Gallery` для отображения каталога.

При получении события `card:select` находит товар
по идентификатору и сохраняет его в модели `Products`.

При получении события `product:selected` получает
данные выбранного товара, определяет состояние кнопки
покупки и открывает подробную карточку в модальном окне.

При получении события `modal:close` закрывает
модальное окно и очищает его содержимое.

При получении события `card:action` проверяет наличие
выбранного товара в корзине, добавляет или удаляет его
и закрывает модальное окно.

При получении события `basket:changed` обновляет
список товаров в корзине, общую стоимость,
состояние кнопки оформления заказа и счётчик
товаров в шапке сайта.

Функция `renderBasket(): void` создаёт карточки товаров
корзины и обновляет её содержимое.

При получении события `basket:open` отображает
корзину в модальном окне.

При получении события `basket:remove` находит товар
по идентификатору и удаляет его из корзины.

При получении события `order:open` получает данные
покупателя и ошибки валидации, открывает первую
форму оформления заказа и определяет состояние
кнопки «Далее».

При получении события `payment:change` сохраняет
выбранный способ оплаты в модели `Buyer`.

При получении события `form:change` определяет
изменённое поле формы и сохраняет его значение
в модели `Buyer`.

При получении события `buyer:changed` получает
актуальные данные покупателя и ошибки валидации,
обновляет обе формы оформления заказа, отображает
ошибки и управляет состоянием кнопок отправки форм.

При получении события `order:submit` проверяет
данные первой формы и открывает вторую форму
оформления заказа.

При получении события `contacts:submit` проверяет
данные покупателя, формирует объект заказа и отправляет
его на сервер.
После успешного оформления заказа очищает корзину
и данные покупателя, отображает сообщение об успешной
покупке с итоговой стоимостью заказа.
